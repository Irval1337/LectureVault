# LectureVault — пользовательские сценарии (v3.2, 11.11.2026)

## Информационная архитектура

Studio workspace: **rail44px** с переходами библиотека/создание/очередь, **Explorer236px** (пространство → курсы → конспекты), **содержимое**, **инспектор244px только у статьи/задания**. В библиотеке и форме инспектора нет. В статье переключаются настоящее Quartz-оглавление и сведения об источнике; в очереди — стадии выбранного задания. Сверху обозначение текущего файла/экрана и компактная toolbar с breadcrumbs. Глобальный «Новый конспект» без курсов открывает создание первого курса и продолжает форму. Создание курса из заполненной формы сохраняет источник/параметры/инструкции. Ctrl/Cmd+K раскрывает проводник и фокусирует поиск; панели можно скрыть/восстановить. На mobile Explorer в drawer, TOC раскрывается в статье, источник/стадии доступны в содержимом. Пустое состояние — короткая подсказка и создание курса. Текст ридера Source Serif 4, технический UI Inter.

### Отдельный просмотр примеров

Ссылка «Демонстрационная библиотека» открывает `/demo`: три курса и восемь конспектов, отдельный насыщенный Markdown-пример. Поиск, дерево, TOC, тема и скачивание работают. Выход возвращает в пользовательскую библиотеку; её localStorage, черновик и пространство не меняются. Демо-данные не добавляются при обычном старте.

### Роли и места создания — план к 19 ноября

- Глобальный `Новый` → выбрать **«Создать заметку» / «Сгенерировать конспект»**; затем выбрать доступный курс. При отсутствии курсов сначала создать первый, вернуться к выбранному сценарию.
- Кнопка `+` у курса → те же действия, но пространство и курс предзаполнены.
- Оба сценария используют одну модель Note и общий Milkdown Crepe. Ручная пустая заметка не создаёт job и не требует источника; в промежуточном прототипе этот сценарий пока отсутствует.
- В личном пространстве заметки приватны по умолчанию. В общем пространстве заметки по умолчанию доступны участникам согласно ролям.

## Главный сценарий для 11 ноября: демонстрационный

1. Пользователь открывает библиотеку (пустое состояние) → `Новый`.
2. Форма: переключатель `Ссылка / Видео файл`; необязательные слайды, режим `Лекция/Семинар`, объем, инструкции; если начато в курсе, он выбран автоматически.
3. Валидация; кнопка `Создать` → карточка job в очереди. Стадии **помечены mock**, нет выдуманного процента готовности.
4. В очереди после демонстрационного завершения появляется `Открыть конспект`.
5. Статья: Markdown, TOC, Explorer, скачивание .md и тема ридера. Неработающие кнопки редактирования не показываются; настоящий Milkdown подключается на следующем этапе.

## Главный сценарий для 19 ноября: реальный

1. Демовход пользователь A, создать общий курс «АКОС» → `+` → «Сгенерировать конспект».
2. Выбрать видеофайл (при готовности также URL через yt-dlp), PDF и инструкции; режим «Лекция»; отправить.
3. В общей очереди `queued → acquiring → transcribing → preparing → generating → ready`. Можно уйти в библиотеку и вернуться, состояние сохраняется. Если failed — посмотреть короткое сообщение об ошибке и `Повторить`.
4. Открыть статью; слева курс/другие статьи, справа TOC, внутри Markdown/LaTeX/изображения. Таймкоды — как ссылки на источник, если реально доступны; иначе не рисовать фиктивные.
5. `Редактировать` → по умолчанию Milkdown Crepe → опционально `Исходный Markdown` в CodeMirror → `Сохранить` → статус сохранения → вернуться в чтение. Обновить страницу → правки остались. Скачать `.md`.
6. Открыть доступ к курсу пользователю B с ролью editor; B видит/редактирует общий конспект. Viewer не может сохранять правки. Если документ изменился между открытием и сохранением, не перезаписывать молча — показать конфликт ревизий.

## Ручная заметка — обязательный дополнительный сценарий к 19 ноября

1. В любом курсе с правом записи `+` → «Создать заметку»; при глобальном «Новый» выбрать курс. Если курсов нет, создать первый и продолжить ручной сценарий.
2. Сохранить Note с названием «Без названия» и пустым Markdown; открыть общий Milkdown Crepe. В дереве уже есть новый документ, очередь не меняется, видео/URL/PDF не требуются.
3. Изменить название и содержание → «Сохранить» → чтение. Пустое тело тоже допустимо; собственный Markdown-редактор не разрабатывается.
4. Открыть из дерева → обновить страницу → отредактировать в том же Crepe → переименовать → скачать `.md`. Название и содержимое сохраняются, ID/ссылка не меняются; экспорт использует новое имя.
5. Проверить формулы, таблицы, изображения и fenced code после сохранения/повторного открытия. При ошибке или конфликте409 сохранить черновик; viewer/постороннему создание, изменение и переименование запрещает сервер.

Ручная и сгенерированная Note имеют общие чтение/редактирование/сохранение/переименование/экспорт и ACL/revision. Источник и job — необязательные связи. У ручной страницы нет выдуманной стадии, mock-метки или пустой вкладки источника; TOC строится по реальным заголовкам. Реализация — на этапе Note/API и Crepe после промежуточной сдачи, без изменения текущего прототипа.

## Навигация и состояния интерфейса

| Экран | Базовые состояния | Действия |
|---|---|---|
| Личная/общая библиотека | пусто; есть курсы; результаты поиска; нет доступа | создать; открыть; раскрыть курс |
| Новый конспект | пустая форма; файл выбран; URL введен; ошибка формата; submit | выбрать источник/пресет; добавить материалы; создать |
| Очередь | пусто; несколько задач; queued; running с этапом; failed; ready; cancelled | открыть; повторить; отменить ожидающее |
| Статья | загрузка; готова; нет доступа; не найдена | TOC; изменить видимость; редактировать; скачать |
| Редактор | dirty; saving; saved; save failed; revision conflict | WYSIWYG/Markdown; сохранить; отменить |
| Общий курс | участники; список заметок; отсутствие прав | пригласить; сменить роль (owner) |

## Что обозначают «режимы»

- Генерация: предустановленные `Лекция`, `Семинар`. В продукте позже `Свой шаблон`.
- Документ: `Чтение`, `Визуальное редактирование`, `Markdown исходник`.
- Библиотека: `Моя`, `Общая`.
- Видимость: `Приватный`, `По ссылке`, `Публичный`. В MVP это локальная демо-модель, без открытого интернет-деплоя.

## Ошибки и edge cases

- URL недоступен / yt-dlp не поддерживает источник → пользователю показана причина без команд shell или секретов.
- Пользователь уходит со страницы задания → работник продолжает, при возврате показан фактический статус.
- Ненужные повторные клики по `Создать` не дублируют отправку одного submit.
- Пустая библиотека содержит единственное ясное основное действие, а не фальшивые карточки.
- В Markdown из консспекта изображения могут ссылаться на Obsidian `![[...]]`: перед рендерингом нужны корректные ссылки на assets; не терять исходный markdown при ошибке конверсии.
- Смена режима редактора не уничтожает несохраненные изменения; confirm при потенциальной потере.
- Публичные/по ссылке документы через mock-login не считаются защищенными; до реальной авторизации не размещать пользовательские данные в сети.

## UX-исследование для защиты проекта

Дать 2–3 знакомым студентам пройти сценарий «добавь запись → найди созданный конспект → исправь формулу → скачай». Зафиксировать, где возникают лишние клики/путаница, и отразить исправления в DESIGN.md и рефлексии. Не выдавать это за формальное требование лектора.

## Уточнение согласованного промежуточного сценария

Курс → видеофайл или ссылка → необязательный PDF → название, курс, Лекция/Семинар, объём и инструкции → mock-задание → очередь → учебный Markdown → скачивание. Курсы/конспекты/очередь и раскрытие дерева переживают refresh через localStorage; mock-стадии восстанавливаются по сохранённому времени и выполняются последовательно. Ссылки и файлы не отправляются на сервер. Личное/общее пространство — локальный фильтр, а не готовая многопользовательская защита.

На итоговом этапе локальное видео через Whisper и Claude обязательно. Затем Crepe с сохранением; PDF — первая дополнительная интеграция, CodeMirror после рабочего основного пути, URL только после SSRF-защиты. Все данные результатов — внутри LectureVault, без записи в личный vault.
