# LectureVault

Библиотека Markdown-заметок с деревом категорий, совместным доступом и необязательной генерацией из видео/PDF. **Studio + Quartz Editorial**, четыре оригинальных референса в `docs/reference/`. Новый аккаунт начинает с пустой библиотеки; демопользователей и демонаполнения нет.

## Локальный запуск

Нужны Docker Engine, Compose **v2.24.4+** и Linux с **Landlock ABI 3+** (ядро 6.2+, включая проверенный WSL2). На несовместимом ядре обработчики отказываются запускаться; небезопасного fallback нет.

```bash
docker compose up -d --build
```

Приложение: **http://localhost:5180**. Письма локальной разработки: **http://localhost:8026** (Mailpit, только loopback). Зарегистрируйтесь со своим email, откройте письмо подтверждения в локальном Mailpit и подтвердите аккаунт. Эта конфигурация не отправляет письма в интернет и не публикует сайт. `LV_PUBLIC_URL` должен совпадать с адресом, который открывает браузер; при смене порта меняйте и его.

Первый build собирает whisper.cpp и скачивает проверенную по SHA-256 модель Whisper tiny (~75 МБ). Обработка/CLI работают с UID10001, web — UID101. Данные и индивидуальные CLI-профили — в именованных volumes. Для перезапуска используйте `docker compose restart` или `down` без `--volumes`.

Новый Compose project называется `lecturevault-service`: прежние учебные volumes проекта `lecturevault` не удаляются и не переносятся в чужие зарегистрированные аккаунты. Старую frontend-библиотеку можно импортировать явной кнопкой; её исходный localStorage сохраняется.

Для разработки frontend после запуска Compose:

```bash
npm ci
npm run dev
```

**http://localhost:5173**, `/api` проксируется на5180. Production preview — `npm run build && npm run preview` (4173). Черновики браузера привязаны к origin и UUID пользователя; сессия хранится в HttpOnly cookie.

## Работа с заметками

1. Регистрация → подтверждение email → пустая библиотека → «Создать категорию». В библиотеке можно выбрать родительскую категорию сразу при создании. На странице категории кнопки «Создать подкатегорию» и «Добавить заметку» уже учитывают текущую ветку. Под названием категории можно сменить значок. В меню «…» владелец может переименовать категорию или выбрать «Объединить с родителем». Во втором случае заметки и подкатегории переходят к родителю, а ссылки на заметки сохраняются.
2. **Новый → Создать заметку** сохраняет пустую Note и открывает готовый Milkdown Crepe. Можно писать без AI, переименовывать, сохранять, читать, редактировать исходный Markdown в CodeMirror и скачивать `.md`. Ctrl/Cmd+S сохраняет; конфликт ревизий409 сохраняет черновик.
3. В **Настройки → Подключения** доступны вход в Codex и **Свой API**. Для ручных заметок подключение модели необязательно.
4. **Новый → Сгенерировать конспект**: видео MP4/MOV/MKV/WebM до512МБ, необязательный PDF до50МБ, язык, Лекция/Семинар, объём, инструкции, провайдер/модель/effort. Без подключения отправка блокируется до загрузки файла.
5. Очередь сохраняется сервером; можно уйти со страницы, отменить ожидающую свою задачу и повторить ошибку. Прерванная при аварии попытка становится failed/INTERRUPTED; готовый документ не дублируется.
6. Результат открывается через настоящие Quartz ContentBody/TOC: KaTeX, таблицы, код, изображения, мобильное оглавление и внутренняя прокрутка широких блоков. Редактор и Note общие с ручными заметками.
7. Корневую категорию изначально видит только владелец. **Доступ** добавляет существующего подтверждённого пользователя по email: viewer читает/экспортирует, editor создаёт/редактирует/удаляет заметки; owner управляет участниками и категорией. Чужие данные недоступны по прямому API/asset/export.

В настройках: имя, смена пароля, выход из всех сессий, отключение провайдеров, удаление собственного аккаунта и принадлежащих ему категорий после подтверждения паролем. Категории других владельцев сохраняются.

## Подключения и обработка

**Codex:** официальный device-code flow, пригодный для удалённого сервера: кнопка → официальная страница OpenAI → одноразовый код → автоматическое обновление статуса. OpenAI может требовать разрешить device login в настройках безопасности ChatGPT; подсказка свёрнута в «Не получается войти?». Loopback OAuth-порт1455 больше не нужен. Access/refresh tokens остаются в индивидуальном серверном профиле, браузер их не получает. Нужен собственный доступ к Codex и выбранной модели. [Официальная документация](https://learn.chatgpt.com/docs/auth).

**Claude Code.** Откройте «Настройки → Подключения → Claude Code» и введите ключ Anthropic API. Адрес сервиса уже задан. Если в «Свой API» используется `https://api.anthropic.com/v1`, Claude Code может использовать то же подключение. Ранее сохранённый отдельный ключ Claude Code имеет приоритет.

**Свой API.** Укажите Base URL и ключ сервера с интерфейсом OpenAI Chat Completions. Для OpenAI адрес `https://api.openai.com/v1`, для Gemini — `https://generativelanguage.googleapis.com/v1beta/openai`. Broker читает модели из `GET /models` и сохраняет каталог отдельно для каждого подключения на 6 часов. Если сервис не реализует список моделей, в форме доступен ввод идентификатора. Для Codex список и уровни рассуждения предоставляет установленный CLI.

Для Ollama на машине с Docker задайте `LV_LOCAL_MODEL_BASES=http://host.docker.internal:11434/v1` и пересоздайте контейнер providers. Сервис Ollama должен быть доступен этому контейнеру по указанному адресу. Введите этот же Base URL в настройках. Установка допускает пустой ключ только для локального адреса, разрешённого оператором. Разрешение локального сервиса без ключа даёт зарегистрированным пользователям возможность вызывать его модели.

При генерации ffmpeg извлекает звук, Whisper распознаёт речь, Poppler извлекает текст PDF, выбранная модель возвращает Markdown. В ридере доступны встроенные изображения слайдов, просмотр всех страниц и оригинальный PDF. Для старых конспектов ридер использует уже прикреплённый файл. Просмотр требует доступа к категории. Пределы — два часа видео, 500 страниц PDF, 140 000 символов расшифровки и 40 000 символов текста слайдов (для длинных презентаций используются выдержки, полный PDF доступен в ридере). Для сканов доступен просмотр изображений, OCR отсутствует.

Повторная загрузка тех же байтов в одну корневую категорию сохраняет отдельные ссылки на вложения и переиспользует файл. Расшифровку можно использовать повторно при том же языке и версии обработчика. Для PDF кэшируются извлечённый текст и запрошенные страницы. Новый запрос к модели выполняется при каждой генерации, с выбранными для этого задания параметрами. Квота по-прежнему учитывает размер каждого вложения.

В рабочем UI нет mock, `/demo` и выбора учебных профилей. Тестовый mock-адаптер доступен **только** при `LV_ENV=test`; development/production отвергают такие запросы. Fixtures нужны тестам и не наполняют пользовательские аккаунты.

## Публикация

Подготовлена отдельная конфигурация HTTPS/Caddy и настоящего SMTP. Пока у владельца нет домена и SMTP, публичная публикация не выполнялась. Полная инструкция, резервное копирование и восстановление — [SECURITY_AND_DOCKER.md](SECURITY_AND_DOCKER.md). Публичный запуск требует собственного хоста, DNS, домена, SMTP с TLS и контакта поддержки; insecure production settings не принимаются.

## Quartz и данные

Оригинальные `@quartz-community/content-page@1.0.0`, `@quartz-community/table-of-contents@1.0.0` работают через Preact. React-дерево получает только доступные пользователю данные API. `vendor/quartz5` содержит SCSS5.0.0, MIT и provenance/SHA-256. Unified/remark/rehype/KaTeX и Milkdown/CodeMirror используются готовыми; собственный Markdown-движок или редактор не написан. GFM/LaTeX/image/code round-trip проверяется, произвольные Obsidian-плагины не обещаются.

Существующие konspekt, Obsidian, hse-notes, `.bashrc`, личный vault и host CLI не меняются. Автоматической публикации документов или Git push нет. Uploads, DB, secrets, profiles и test-results исключены из Git/build context.

## Проверки

```bash
npm test
npm run build
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt
npm run test:api
npm run test:e2e
.venv/bin/python tests/run_https.py
```

Browser-приёмка создаёт отдельный Compose project и удаляет только его временные volumes/images: реальные регистрации/SMTP-подтверждения, ручные заметки, роли, конфликты, очередь через test-only адаптер, импорт, мобильный ридер, настройки. Снимки1440×1000/768/390×844 и traces — в игнорируемом `test-results/`. Нужен Chromium (`npx playwright install chromium` или `CHROMIUM_PATH`). `TEST_BASE_URL` использовать только с выделенным тестовым экземпляром: сценарии создают и удаляют собственные данные.

HTTPS-приёмка использует production overlay, Caddy с **локальным тестовым сертификатом**, SMTP AUTH+STARTTLS с проверкой тестового CA, Secure/HttpOnly/__Host cookie, регистрацию и сохранение. Не меняет host trust store и не отправляет настоящих писем; это не проверка публичного ACME/DNS и внешней доставляемости. Платные AI-запросы автоматически не запускаются.

Спецификации: [PRD](PRD.md), [DESIGN](DESIGN.md), [сценарии](USER_FLOW.md), [актуальный план](docs/production-plan.md), [исходный согласованный план](docs/plan-2026-11-10.md). Production build сообщает о размере лениво загружаемого готового редактора; это остаётся известным ограничением загрузки.

Проверки охватывают отзыв роли во время обработки, содержимое резервного архива, возврат из подключений в форму с выбранными файлами и редактирование во время сохранения. Интеграционный тест OpenAI проходит от загрузки видео/PDF через очередь до редактируемой Note и экспорта с тестовыми ответами распознавания и внешнего API. Проверка платного запроса требует личного ключа и бюджета. Порядок запуска проверок приведён выше.

Очередь выполняет до двух заданий одновременно. Whisper занимает один вычислительный слот. Запросы к совместимому HTTP API могут выполняться одновременно, запуск CLI в одном профиле сериализован. Число слов служит ориентиром модели. Предел иллюстраций ограничивает вставки слайдов в Markdown.

В одном списке видны собственные категории и категории с предоставленным доступом. Одноразовую ссылку создаёт владелец в «Доступе». Она действует 24 часа, её можно заменить или отозвать. Для принятия требуется вход в аккаунт.
