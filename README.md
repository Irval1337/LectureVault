# LectureVault

Локальная библиотека учебных заметок: курсы → видео и PDF → очередь → Markdown → редактирование. Дизайн **Studio + Quartz Editorial**, четыре оригинальных референса в `docs/reference/`.

## Запуск

Требуются Docker Engine и Compose v2. Из корня проекта:

```bash
docker compose up -d --build
```

Приложение: **http://localhost:5180**. Первый build скачивает зависимости CLI, собирает whisper.cpp и загружает проверенную по SHA-256 модель Whisper tiny (~75 МБ). Сервисы обрабатывают файлы с UID 10001, web работает с UID 101. Данные сохраняются в именованных Docker volumes. Обычный `docker compose down` их сохраняет; `down --volumes` удаляет, поэтому для перезапуска его не используйте.

Для frontend-разработки после запуска Compose:

```bash
npm ci
npm run dev
```

Адрес: **http://localhost:5173**, `/api` проксируется в Compose. `npm run build` и `npm run preview` дают production preview на 4173 с тем же API. Сохранённые документы общие между портами; черновики и настройки браузера привязаны к origin и пользователю.

## Пользовательский сценарий

1. Выберите **Алексей** или **Мария**. Это локальные демопрофили, без регистрации и пароля.
2. Создайте курс в личном или общем пространстве. Общий курс виден второму демопользователю; владелец меняет его роль через **Доступ**.
3. **Новый → Создать заметку** сразу сохраняет пустой Markdown и открывает готовый Milkdown Crepe. Название и текст редактируются там же; вкладка Markdown использует готовый CodeMirror. Сохранение, переименование, дерево и экспорт общие с результатами генерации.
4. **Новый → Сгенерировать конспект**: загрузите видео MP4/MOV/MKV/WebM до 512 МБ, при необходимости PDF до 50 МБ; выберите язык, Лекцию/Семинар, объём и инструкции.
5. В реальном режиме выберите Codex или Claude, модель и effort. **Войти в Codex/Claude** в форме либо имя пользователя внизу проводника открывает подключения. Codex открывает обычный браузерный вход; после подтверждения статус обновляется автоматически. Для Claude официальный CLI может дополнительно запросить код со своей страницы. CLI-токены браузеру не передаются.
6. Очередь работает по одному заданию. Можно уйти со страницы и вернуться, отменить ожидающее или повторить ошибку. После перезапуска worker прерванная попытка отмечается ошибкой с возможностью повтора.
7. Готовая Note открывается в настоящих Quartz ContentBody/TOC: Markdown, KaTeX, таблицы, код и изображения. Редактирование, сохранение с проверкой ревизии и скачивание `.md` работают для обоих способов создания.

Для Codex браузерный callback использует **127.0.0.1:1455**; порт публикуется только на loopback. Браузер должен работать на машине запуска Compose. При удалённом Docker нужны SSH-туннели для приложения и 1455. Одно подключение сохраняется между перезапусками в отдельном профиле соответствующего демопользователя. Существующие профили host CLI не копируются и не изменяются. Нужны собственный доступ/подписка и доступная выбранная модель; бесплатная генерация не обещается.

## Реальная обработка и демо

**Реально:** ffprobe/ffmpeg → whisper.cpp → текст PDF через Poppler (если приложен) → Codex либо Claude CLI без инструментов → Markdown в SQLite. Видео до двух часов; PDF до 100 страниц с выделяемым текстом; до 140 000 символов транскрипта и 40 000 символов PDF. При превышении — явная ошибка, текст не обрезается молча. На проверенном окружении нет NVIDIA Container Runtime, поэтому используется изолированный CPU runner с Whisper tiny. CUDA и качество расшифровки длинных лекций здесь не заявляются.

**Демо без анализа:** явно помеченный mock-конспект из `fixtures/demo-note.md`, около 6 секунд на задание. Видео/PDF сохраняются на локальном сервере, но не анализируются. URL разрешён только в демо и никогда не запрашивается по сети. `https://error.example/lecture` даёт искусственную ошибку первой попытки для проверки повтора. Ошибка реального задания не заменяется mock.

`/demo` — отдельная read-only библиотека примеров (три курса, восемь документов), доступная без входа. Она не наполняет пользовательские библиотеки. Старый `lecturevault.library.v1` импортируется только по кнопке, в личные курсы; исходный localStorage не удаляется. Старые задания остаются в исходной копии, медиа в прежнем прототипе не хранились.

## Данные и безопасность

- FastAPI + SQLite WAL: курсы, участники, единая Note, ревизии, задания, сессии и защищённые вложения. Owner/editor/viewer проверяются на сервере, включая прямые запросы к документам, источникам и экспорту. Управление заданием — только его отправителю.
- Сессия — HttpOnly/SameSite cookie, защита изменяющих запросов, localhost Host/Origin, ограничения размеров и числа заданий. Черновики и настройки браузера раздельны по демопользователям. При конфликте 409 черновик можно скачать, затем явно загрузить актуальную версию.
- Медиаобработчик без внешней сети, аккаунтов CLI и доступа к API; авторизованные CLI — в отдельных контейнерах и home volumes для каждого пользователя, без медиа, базы, vault или docker.sock. Раздельные RPC-секреты. Никакого `shell=True`, произвольных CLI-флагов или путей из ввода пользователя.
- 512 МБ видео / 50 МБ PDF / 10 МБ PNG/JPEG/WebP, максимум 10 активных задач пользователя и 3 ГБ вложений на экземпляр. MIME/signature и серверные имена, лимиты страниц/времени/ресурсов; SVG-upload отключён.
- Реальные URL/yt-dlp, OCR, PPTX, realtime, публичная публикация и импорт личного vault отключены. Такая mock-авторизация предназначена **только для localhost**, не для публичного сервера.

Оба демопрофиля выбираются без пароля: любой пользователь с доступом к этому localhost может выбрать любой из них. Это учебная модель доступа, а не защита CLI-аккаунтов от другого человека на той же машине. Не публикуйте порты наружу. Секреты, загруженные материалы и база находятся только в volumes и не входят в Git/build context.

## Quartz и редакторы

Оригинальные `@quartz-community/content-page@1.0.0`, `@quartz-community/table-of-contents@1.0.0` используются через Preact. Динамическое дерево React заменяет зависимый от статического contentIndex Explorer. В `vendor/quartz5` — исходные SCSS 5.0.0, MIT-лицензия и provenance/SHA-256. Готовый unified/remark/rehype + KaTeX; собственный Markdown-движок не написан. Milkdown Crepe/CodeMirror используются без собственной реализации редактора. Базовый GFM/LaTeX/image/code round-trip проверяется; совместимость произвольных Obsidian-плагинов не заявляется. Markdown экспортируется без переписывания при чтении.

Существующие konspekt, Obsidian, hse-notes и CLI-настройки не меняются. Публикация в Quartz и Git push автоматически не выполняются.

## Проверки

```bash
npm test
npm run build
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements-dev.txt
npm run test:api
npm run test:e2e
```

Browser-приёмка сама поднимает отдельный Compose project с временными volumes, проверяет production UI при 1440×1000, 768px и 390×844 и удаляет только свои ресурсы. Нужен установленный Chromium (`npx playwright install chromium` либо `CHROMIUM_PATH`). `TEST_BASE_URL` позволяет указать уже запущенный экземпляр; тесты создают в нём свои курсы, поэтому используйте отдельное тестовое окружение. Скриншоты и traces пишутся в игнорируемый `test-results/`. CLI OAuth и платная генерация не запускаются автоматическими тестами; настоящий сквозной путь проверяется отдельно с явным аккаунтом.

Claude без доступной подписки и полный новый браузерный OAuth с повторным подтверждением пользователя не объявляются сквозным образом проверенными: действующее подключение сохранено, запуск browser-flow и защита callback/state проверены отдельно. Сборка содержит предупреждение о размере лениво загружаемого готового редактора; оно не блокирует build.
