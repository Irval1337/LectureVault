# LectureVault

Локальная библиотека конспектов: курсы → источники → очередь → Markdown-страницы. Промежуточный прототип для сдачи **11 ноября 2026**. Генерация полностью демонстрационная; настоящее видео, Whisper, Claude и backend сейчас не подключены.

## Текущая визуальная версия — Studio

Frontend: **http://localhost:5173**; отдельная [демонстрационная библиотека](http://localhost:5173/demo). Принято направление **B Studio + типографика A**: rail44, проводник236, полезный инспектор244, serif-ридер и общий компактный UI для библиотеки, формы и очереди. Исходные данные localStorage v1 и черновики сохраняются.

[DESIGN v3.2](DESIGN.md) (текущий Studio и план ручных заметок к 19 ноября) · [План реализации](docs/plan-2026-11-10.md).

Финальный polish: создание первого курса возвращает в заполненную форму; rail переключает разделы, проводник содержит дерево; метаданные от 12px. Широкие таблицы/код/формулы имеют внутреннюю прокрутку с клавиатурным управлением. Production build, 15 unit и 9 browser-сценариев проходят.

Docker-контейнер на5180 в этой UI-итерации не пересобирался и показывает прежнюю сборку. Docker/backend/pipeline и npm-зависимости не изменялись.

## Запуск

Из корня проекта:

```bash
cp .env.example .env
docker compose up --build -d
```

Открыть **http://localhost:5180**. Порт 8080 этой машины уже занят другим проектом и не изменялся. Другой порт можно задать через `LECTUREVAULT_PORT` в `.env`.

```bash
docker compose ps
docker compose logs --tail=50 web
docker compose down
```

`web` работает с UID 101, read-only filesystem, ограничениями ресурсов и bind только на 127.0.0.1. В этой фазе нет API, runner, host mounts или обработки пользовательских файлов. `COMPOSE_BAKE=false` в `.env.example` обходит сбой установленного Compose 2.40.3 в Bake builder; глобальные настройки Docker не меняются.

Альтернатива для разработки (Node.js 24, npm 11):

```bash
npm ci
npm run dev
```

Адрес разработки: **http://localhost:5173**. Сборка и просмотр production-версии:

```bash
npm run build
npm run preview
```

Preview: **http://localhost:4173**. localStorage привязан к точному origin: разные порты и `localhost`/`127.0.0.1` имеют отдельные библиотеки. Для демонстрации используйте один адрес.

## Что работает

- Отдельная демонстрационная библиотека `/demo`: три курса и восемь примеров, без записи в пользовательский localStorage.
- Пустая личная/общая библиотека, создание курсов, переходы по дереву и раскрытие курсов.
- Глобальное и контекстное создание конспекта, выбор/drag-and-drop видео MP4/MKV/MOV/WebM до 512 МБ либо HTTP(S)-ссылки; необязательный PDF до 50 МБ.
- Название, курс, Лекция/Семинар, объём и инструкции. Проверка полей не очищает форму; черновик восстанавливается после refresh.
- Сохраняемая последовательная mock-очередь, стадии, фильтры, отмена ожидающего, ошибка/повтор. Демо-обработка занимает около 12 секунд на задание и восстанавливается по сохранённому времени.
- Оригинальные Quartz 5 ContentBody и TableOfContents через Preact; готовый unified/remark/rehype renderer, GFM, KaTeX, код, таблицы и демонстрационное изображение.
- Studio rail/проводник, Ctrl/Cmd+K, скрытие/восстановление панелей и доступные tab-переключатели.
- Навигация по оглавлению, инспектор «Оглавление / Источник», поиск по названиям курсов/конспектов, независимая светлая/тёмная тема статьи, скачивание `.md`.
- localStorage: курсы, тексты, задания, настройки, раскрытие дерева и тема переживают перезагрузку. Мобильный drawer, Escape/focus trap и адаптивность 1440/768/390 px.

## Что означает mock

Видео и PDF **не читаются, не загружаются на сервер и не сохраняются**: приложение хранит только имя/размер выбранного файла. По URL не выполняется ни одного сетевого запроса. Вместо анализа источника создаётся явно помеченный учебный конспект о репликации из `fixtures/demo-note.md`. Пресет и объём меняют только вариант демопримера; инструкции и PDF записываются как параметры, но не участвуют в анализе.

Для проверки failed/retry предусмотрен синтетический источник `https://error.example/lecture`: первая попытка заканчивается демонстрационной ошибкой, повтор успешен. Сеть при этом не используется.

Личное/общее пространство — локальное разделение материалов одного браузера. Авторизации, двух аккаунтов, серверных ACL, редактирования, настоящего pipeline и публикации пока нет. В интерфейсе отсутствуют фиктивные кнопки этих функций.

## Переиспользование Quartz

Ограниченный технический эксперимент подтвердил работу оригинальных `@quartz-community/content-page@1.0.0` и `@quartz-community/table-of-contents@1.0.0`: они реально используются в ридере. Оригинальный Explorer зависит от глобальной навигации/contentIndex и восстановления функций через `new Function`; для него применён согласованный динамический вариант дерева React.

В `vendor/quartz5` находятся только SCSS ядра версии 5.0.0, MIT-лицензия и SHA-256/provenance. Исходные стили подключены в CSS layer, пользовательская тема задана отдельно. Сайт не выдаётся за целиком работающий на Quartz. Персональная конфигурация и контент `hse-notes` не копировались. Самописного Markdown-движка нет. Канонический Markdown позволяет позднее сделать отдельный публичный экспорт.

Варианты дизайна, история скриншотов, разовые скрипты и отчёты удалены из рабочего дерева; прежние версии доступны в Git. `fixtures/` нужны текущей mock-генерации и `/demo`, `vendor/quartz5/` — стилям ридера и лицензии.
