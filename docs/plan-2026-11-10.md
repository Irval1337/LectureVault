# LectureVault — согласованный план, 10 ноября 2026

Статус на 17 ноября: промежуточный прототип завершён, итоговый backend/runner/editor разрешён поручением «доделать задание полностью». Ниже сохранён исходный план; актуальные решения и границы — в разделе «Актуализация 17 ноября» и CODEX_PLAN.md.

## Приоритет и результат 11 ноября

Главное — законченный UX по DESIGN.md и четырём пользовательским референсам: создать курс → добавить видеофайл или ссылку → настроить Лекцию/Семинар, объём, инструкции, необязательный PDF → создать mock-задание → наблюдать последовательную очередь → открыть готовый Markdown → перейти по библиотеке и скачать .md.

React + TypeScript + Vite, Tailwind и shadcn/ui. Курсы, документы, настройки и mock-задания сохраняются в localStorage; исходные видео/PDF не сохраняются и не отправляются. Mock явно обозначен. Все видимые действия работают. Библиотека начинается пустой; демонстрационные материалы создаются только явным действием пользователя. Тёмная трёхколоночная библиотека Quartz, без шаблонного SaaS-дашборда. Проверки 1440/390 px, настоящие скриншоты прототипа и сценарий видео до минуты.

## Quartz: ограниченный эксперимент и готовый fallback

До 60 минут проверить оригинальные компоненты Quartz 5 (Explorer, TOC, ContentBody) в изолированных Preact-контейнерах React. Условия продолжения: небольшой мост, стабильные повторные переходы/cleanup, отсутствие общего индекса приватных документов и существенных изменений upstream.

Если условия не выполнены, немедленно применить согласованный fallback: react-markdown + готовые remark/rehype-плагины GFM/KaTeX, стили и структура Quartz, динамическое дерево библиотеки. Собственный Markdown-движок и переписывание Quartz запрещены. Допустимо частичное переиспользование стабильных компонентов. Заимствованные исходники сопровождаются лицензией и происхождением. Не копировать персональный контент и настройки hse-notes. При запуске приложение не зависит от старого репозитория. Markdown и относительные вложения остаются пригодными для будущего публичного Quartz-экспорта; экспортёр сейчас не разрабатывается.

## Архитектура итоговой версии 19 ноября

Frontend получает данные через MockRepository, позднее ApiRepository. FastAPI + SQLite + storage + один последовательный worker. Сущности: пользователи, пространства, курсы, членство/роли, папки, заметки с Markdown/revision, вложения, задания. API проверяет каждую операцию с заметками, вложениями, курсами и заданиями. Два демопользователя, личные библиотеки и общий курс, роли owner/editor/viewer. Минимальная проверка revision возвращает 409 при конфликте и сохраняет черновик.

Стадии: queued/acquiring/transcribing/preparing/generating/ready, failed/cancelled. Задание сохраняется до выполнения; одна активная попытка; retry/cancel queued; незавершённая попытка после аварии failed с interrupted. Ошибка реальной обработки не заменяется mock.

Обязательный реальный путь: локальное видео → ffmpeg → Whisper → Claude CLI → проверка Markdown → сохранение. Новый адаптер не вызывает функцию konspekt и не подключает .bashrc. Результаты только в LectureVault. CUDA предпочтительна; при блокере GPU-контейнера — согласованный CPU-резерв для короткого настоящего видео.

Сначала готовый Milkdown Crepe и сохранение Markdown для сгенерированных и ручных заметок; затем отдельный CodeMirror для исходника. Одна модель Note и один общий экран редактора Crepe. Проверять round-trip формул, GFM-таблиц, изображений и fenced code. Не писать собственный WYSIWYG.

### Дополнение пользователя от 11 ноября: ручные заметки к 19 ноября

Обязательный итоговый scope: внутри любого курса, где пользователь имеет право записи, можно вручную создать пустую Markdown-заметку без видео, источника и запуска генерации. Глобальная кнопка **«Новый»** и контекстный `+` курса предлагают два действия: **«Создать заметку»** и **«Сгенерировать конспект»**. В контексте курса он уже выбран; при глобальном создании выбирается доступный курс, при отсутствии курсов сначала создаётся первый с возвратом к выбранному сценарию.

Оба пути создают одну сущность **Note**: общий идентификатор, курс, название, канонический Markdown, ревизия, права и даты. Происхождение `manual/generated` — метаданные этой же модели; связь с GenerationJob/NoteSource необязательна. Ручная заметка начинается с `markdown = ''` и названия «Без названия»; пустое тело является корректным сохранённым документом. Создание сохраняет Note, добавляет в дерево и открывает тот же готовый **Milkdown Crepe**, который используется для редактирования результата генерации. Не создавать отдельную модель/формат, редактор или фиктивную задачу для ручных страниц.

Ручная заметка сохраняется, открывается из дерева, редактируется, переименовывается и скачивается как `.md`. Переименование меняет название и имя экспорта, сохраняя ID/ссылку документа. Для ручной страницы без источника не показывать фиктивные источник, стадии обработки или метку mock-генерации. Доступ, ошибка сохранения и конфликт 409 обрабатываются теми же механизмами, что у сгенерированного документа. Несохранённый текст при ошибке не теряется.

Небольшие проверяемые шаги внутри уже запланированной работы:

1. **12–13 ноября, модель/API:** Note может существовать без source/job; разрешены пустое тело и изменение названия. Приёмка: запись переживает рестарт, owner/editor может создать/изменить, viewer и посторонний не могут; старые сгенерированные документы продолжают открываться.
2. **16 ноября, общий Crepe и меню:** добавить два действия «Новый», выбор курса и ручное создание → общий редактор. Приёмка: пустая заметка видна в дереве, создание не добавляет ни одного задания и не вызывает runner; desktop и mobile позволяют выбрать оба сценария.
3. **16 ноября, сохранение/переименование/экспорт:** общие операции Note для обоих путей. Приёмка: ввести заголовки, формулу, таблицу, изображение и код → сохранить → открыть из дерева → reload → переименовать → скачать Markdown без потери содержимого; пустая заметка также сохраняется и экспортируется. Ошибка/409 сохраняют черновик.

Это дополнение не требуется в промежуточном прототипе и не меняет приоритет обязательного настоящего видеопути. Реализация — после сдачи 11 ноября, в существующих этапах Note/API и Crepe, до дополнительных PDF/CodeMirror/URL. Сам backend/runner по-прежнему требует отдельного согласования.

PDF — первая дополнительная интеграция после обязательного пути: ограниченное извлечение текста/растеризация в изолированном обработчике, использование текста слайдов в генерации, сохранение картинок с устойчивыми ссылками. После PDF — CodeMirror, затем URL/yt-dlp только с подтверждённым контролем SSRF на соединениях, DNS и redirect. PPTX, realtime, SSO, граф, импорт vault и публичный Quartz-экспорт за пределами ИДЗ.

## Структура и безопасность

- web/: интерфейс, reader, editor, слой данных.
- backend/: будущие API, SQLite, ACL, worker и адаптеры.
- runner/: будущие изолированные обработчики.
- deploy/: контейнерные настройки; tests/: проверки; docs/: план, референсы, отчёты.
- storage/: только данные LectureVault, вне Git/архива; compose.yaml: воспроизводимый локальный запуск.

Сначала работающий UX, затем простой Compose web. До backend/реальных загрузок — отдельный аудит/согласование prompts/06_docker_security.md. Итоговый Compose: web/api/worker и изолированный runner; медиапарсеры отделены от авторизованного Claude. Non-root обработка, узкие mounts, лимиты ресурсов/файлов/страниц/времени, серверные имена, безопасные argv, без shell=True/eval и произвольных команд. Отдельный новый профиль Claude; не копировать прежние credentials, не передавать их браузеру. Никакого доступа к личному vault, домашним каталогам, docker.sock или privileged-режима. Bind 127.0.0.1; mock-login только локальный. Файлы через API с ACL; raw HTML и опасные embeds отключены. Настройка NVIDIA Container Toolkit — отдельная будущая зависимость, сейчас не устанавливается.

## Актуализация 17 ноября: разрешён итоговый этап

Поручение пользователя «доделать задание полностью» снимает остановку после промежуточного прототипа. Согласован Codex как реальный провайдер наряду с Claude; требуются отдельный вход и выбор модели/effort. Старые указания ожидать разрешения на backend относятся к завершённой сдаче 11 ноября.

Реализованы API/SQLite, серверные права двух пользователей, общий курс, сохраняемая очередь, non-root контейнерные обработчики и отдельные CLI-профили пользователей, ручные Note, общий готовый Crepe и CodeMirror, ревизии и импорт старого localStorage без удаления. Реальное короткое видео с PDF прошло Whisper CPU → Codex → сохранённый Markdown. Claude-адаптер есть, рабочая подписка недоступна: успех Claude не заявляется. Для Codex используется обычный браузерный OAuth, настройки device auth не требуются.

Уточнён минимальный scope: курс → Note без дополнительных папок; PDF с текстовым слоем, без растеризации/OCR; реальные URL отключены, демо-ссылки не запрашиваются. NVIDIA Container Runtime отсутствует — используется согласованный CPU fallback, host-конфигурация не меняется. Public/unlisted, realtime, SSO, PPTX и Quartz publishing не реализуются.

Текущая последовательность и критерии — CODEX_PLAN.md; фактические команды/ограничения — README.md. Повторная browser-приёмка запускается в отдельном Compose project с собственными volumes. Пользовательские volumes, localStorage и CLI-профили не очищаются. Генерируемые скриншоты/видео/архивы вне Git; удалённые submission и экспериментальные документы не восстанавливаются.
