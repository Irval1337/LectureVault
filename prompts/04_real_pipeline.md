# 04 — Реальные данные и существующий konspekt

Прочитай PRD.md v2, CODEX_PLAN.md, USER_FLOW.md, результат read-only аудита.

Реализуй backend FastAPI+SQLite+worker в рамках проекта. Worker получает задания из БД; выполняет их последовательно; перезапуск не теряет очередь. Сохраняй прогресс стадиями и понятные ошибки. Никакой bash shell interpolation пользовательского ввода.

Переиспользуй проверенные инструменты pipeline через новый изолированный адаптер Whisper + Claude CLI; исходную Bash-функцию konspekt и .bashrc не загружай; **не переписывай и не меняй** чужие существующие файлы `/root/.bashrc`, Obsidian и hse-notes. При необходимости предложи новую wrapper-команду внутри папки проекта и согласуй. Сначала обеспечь реальную обработку одного локального видеофайла до итогового Markdown, затем приоритетно PDF-презентацию, потом отдельный CodeMirror и только затем `yt-dlp` с проверенной SSRF-защитой. PPTX остаётся после ИДЗ.

Сначала добавь готовый Milkdown Crepe WYSIWYG и сохранение Markdown, затем отдельный CodeMirror после работающего основного сценария. Не писать собственный редактор. В БД хранить Markdown как источник истины; проверить round-trip на заголовках, ссылках, GFM-таблицах, KaTeX, изображениях и fenced code; при несовместимости не терять содержимое без предупреждения. Храни вложения отдельно в storage с доступом по permissions.

Итоговый scope включает ручные пустые заметки: «Новый» и `+` курса → «Создать заметку» / «Сгенерировать конспект». Одна модель Note с необязательными source/job, один общий Milkdown Crepe для обоих путей. Ручная заметка без видео и запуска runner сохраняется с пустым Markdown, открывается из дерева, редактируется, переименовывается без смены ID и экспортируется. Пустое тело допустимо; права/revision и сохранение черновика при ошибке общие. Не создавать фиктивный job или отдельный редактор. Это работа этапа Note/API и Crepe к 19 ноября, не дополнение к промежуточному прототипу; критерии — docs/plan-2026-11-10.md.

Добавь демо-login и личную/общую библиотеку с двумя mock-пользователями; owner/editor/viewer на уровне курса, без реалтайм-курсоров; оптимистические revisions для предотвращения потери правок. Public/unlisted/private — только демонстрационная модель без обещания безопасности на открытом сервере.

Не создавать fork Quartz как часть критического пути; отдельно по готовности можно экспортировать только публичные Markdown+assets в независимую сборку Quartz с разрешения пользователя. Не делать push.

После работы проверь один реальный сквозной сценарий и верни список ручных проверок. Не называй обработку реальной, если фактически сработал mock adapter.
