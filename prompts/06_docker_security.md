# Codex prompt 06 — Docker и security hardening LectureVault

Прочитай `PRD.md`, `CODEX_PLAN.md`, `README_HANDOFF.md`, затем новый `SECURITY_AND_DOCKER.md`. Этот файл является обязательным дополнительным набором требований. Ранее безопасность была описана только частично, а Docker не был фиксирован как требование.

**Сначала только аудит и план; ничего не меняй до моего подтверждения.**

1. Проверь фактическую структуру проекта, существующий способ запуска, наличие Docker Engine/Compose в Windows+WSL, GPU/CUDA и локальных Claude/Codex CLI. Не выводи в отчет переменные окружения с токенами, конфиги авторизации или содержимое чужих файлов.
2. Определи границы доверия: браузер, API, БД/файлы, worker, `yt-dlp`, `ffmpeg`, Whisper, CLI и public Quartz. Составь краткую threat model (SSRF, RCE/shell injection, path traversal/zip slip, XSS, IDOR, prompt injection, DoS, утечка секретов и документов).
3. Предложи минимальный Docker Compose для `web`, `api`, `worker` и persistent `storage`. Обеспечь локальный bind `127.0.0.1`, non-root где возможно, отсутствие privileged/docker.sock/host mounts, лимиты ресурсов и логов, health checks, корректный restart.
4. Отдельно разберись с `konspekt`: это Bash-функция WSL, а не исполняемый файл. Предпочитай контейнеризированный исполняемый adapter, но **не копируй и не монтируй в контейнер личные CLI credentials**. Если безопасная контейнеризация Codex/Claude/Whisper с GPU сейчас неосуществима, предложи минимальный доверенный host-runner и явно опиши исключение, реальные риски и почему вся система тогда не на 100% Docker. Не изменяй старые скрипты и Obsidian.
5. Составь конкретную последовательность исправлений и acceptance checks из `SECURITY_AND_DOCKER.md`, отсортированную по важности для ИДЗ 11/19 ноября. Не обещай безопасность от произвольных URL, пока не обеспечен transport-level SSRF контроль и redirect/DNS защита.
6. После согласования плана реализуй его этапами и проверь реальные команды запуска, API permission tests, сохранение данных, ошибочные URL/файлы, лимиты очереди и отсутствие секретов в логах. Не используй дополнительные agent skills.

**Готово только если:** проект запускается документированной командой `docker compose up --build`, основной сценарий воспроизводится, данные переживают restart, применены реализуемые требования безопасности; любой host-runner и незащищенные функции явно отмечены в README. Нельзя писать «все в Docker»/«безопасно публиковать», если это не подтверждено.
