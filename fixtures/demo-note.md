# Репликация и консистентность

> Демонстрационный конспект для проверки интерфейса. **Не результат работы LLM.**

## 1. Зачем нужна репликация

Репликация — поддержка нескольких копий данных на разных узлах системы.

- **Отказоустойчивость:** часть узлов может стать недоступной, но копии остаются.
- **Масштабирование чтений:** запросы могут распределяться между репликами.
- **Географическая близость:** чтения можно обслуживать ближе к клиенту.

> Репликация улучшает доступность, но сама по себе не обеспечивает сильную консистентность.

## 2. Линеаризуемость

Операции должны выглядеть как происходящие в некоторой единственной точке между началом и завершением:

$$
 t_{invoke}(op) \le t_{linearize}(op) \le t_{response}(op)
$$

## 3. Пример задержки реплики

```text
Client -> Primary: PUT(key, value)
Primary -> Client: OK
Primary -> Replica: replicate(key, value)
```

Если реплика получает обновление позже, чтение с нее может вернуть устаревшее значение. Конкретные гарантии зависят от выбранного протокола.
