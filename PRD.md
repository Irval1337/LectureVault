# LectureVault — PRD (согласовано 10 ноября 2026)

**Версия:** 3.0, 17 ноября 2026. **Цель:** законченная локальная версия для итоговой сдачи ИДЗ1 19 ноября.

## Реализованный итоговый scope

Сохраняемый FastAPI/SQLite backend; два демопользователя с личными и общими курсами, серверными owner/editor/viewer; последовательная очередь с отменой ожидающих, повтором и восстановлением после аварии. Ручные и сгенерированные документы используют одну Note, общий готовый Milkdown Crepe, CodeMirror для исходника, переименование, ревизии и экспорт. Данные живут в Docker volumes; localStorage хранит черновики/настройки, прежняя библиотека импортируется только явно и не удаляется.

Реальная цепочка локальное видео → ffmpeg/Whisper → необязательный текст PDF → Codex/Claude CLI → Markdown изолирована и работает без root. По просьбе пользователя от 17 ноября Claude дополнен **Codex**, выбором модели/effort и раздельным входом в CLI-профили. Успешно проверено видео + PDF → Whisper CPU → Codex (`gpt-6-luna`, low) → настоящий конспект. Claude-адаптер реализован, но успешный реальный запрос не подтверждён: подписка пользователя недоступна. Нельзя выдавать это за проверенную Claude-генерацию.

Дизайн **Studio + Quartz Editorial** сохранён: rail44px, проводник236px, центр, полезный инспектор244px; Source Serif 4 для статьи, Inter для UI. Настоящие Quartz ContentBody/TOC и стили; своя реализация Markdown или WYSIWYG не создавалась. `/demo` изолирована. Проект запускается Compose на localhost; полный актуальный запуск и ограничения — README.md.

До 11 ноября работал frontend/localStorage mock-прототип. Последующее поручение «доделать задание полностью» разрешает итоговый backend/runner/editor; прежнее требование остановиться перед backend относится к завершённому промежуточному этапу.

## Границы итоговой версии

Курс → Note без дополнительных папок; личный доступ и членство общего курса вместо отдельных public/unlisted переключателей. Источник — локальное видео; URL только mock без сетевых запросов. PDF использует текстовый слой, без OCR и изображений слайдов. Нет PPTX, realtime, публичного Quartz-export, vault-import и SSO. Нет NVIDIA Container Runtime: используется согласованный CPU fallback с Whisper tiny, CUDA не объявлена готовой. Демо-вход без пароля работает только локально.

Ниже описано продуктовое направление и исходные решения; перечисленные расширения не расширяют реализованный scope.

## 1. Зачем и для кого

LectureVault превращает видео, ссылки и сопутствующие учебные материалы в конспекты и организует их в личную и общую базу знаний. Целевая аудитория: студенты, ведущие конспекты, и участники совместных учебных пространств. Основная боль: существующий конвейер `konspekt` → Obsidian → экспорт в Quartz требует CLI, ручной раскладки заметок и не дает другим пользователям понятного способа создать, отслеживать и исправлять конспект.

**Позиционирование:** не чат с AI, не очередная LMS и не генератор отдельных PDF; это рабочее пространство знаний со сквозным процессом «исходный материал → обработка → статья → редактирование/доступ».

## 2. Решения пользователя (фиксированные)

1. **Иерархия:** личные и общие пространства → курсы → папки/подстраницы → Markdown-документы. В MVP достаточно одного вложенного уровня папок, дерево должно быть расширяемым.
2. **Режимы:** лекция/семинар/пользовательский шаблон генерации; чтение/визуальное редактирование/исходный Markdown; личная/общая библиотека. Пользовательские шаблоны — в целевом продукте, в MVP только готовые пресеты.
3. **Создание к 19 ноября:** глобальная кнопка «Новый» и контекстный `+` курса предлагают «Создать заметку» / «Сгенерировать конспект». Ручная пустая Markdown-заметка не требует видео/job. Оба пути используют одну Note и один готовый Milkdown Crepe; результат помещается в выбранный курс. Для промежуточного прототипа ручное создание необязательно.
4. **Задания:** отдельная очередь с несколькими элементами, последовательной обработкой на backend и статусами; просмотр журнала, повтор неудачного, отмена ожидающего; прерывание активного — только если безопасно реализовано.
5. **Источники:** URL через `yt-dlp` (best effort), видеофайлы, опциональные PDF/PPTX/дополнительные файлы и инструкции. Для MVP таймкоды — опция, если извлечение надежно; полноэкранная синхронизация видео/слайдов/транскрипта — позже.
6. **Редактор:** готовый WYSIWYG Markdown (предпочтительно Milkdown Crepe) + просмотр/редактирование исходного Markdown (CodeMirror). Markdown остается каноническим форматом. Не делать редактор с нуля.
7. **Сотрудничество:** пользователь может создать общий курс, пригласить участников и совместно наполнять его конспектами. Одновременное редактирование одной страницы, live-курсоры и Google-Docs-подобная синхронизация — после ИДЗ.
8. **Навигация:** трехколоночный Quartz: Explorer слева, статья по центру, оглавление/граф справа; без обязательных вкладок Obsidian.
9. **Импорт:** начать с пустой библиотеки; миграцию существующего Obsidian vault не делать в ИДЗ.
10. **Видимость:** в итоговой версии права наследуются от личного/общего курса. Режимы unlisted/public относятся к дальнейшему развитию и не показываются фиктивными переключателями. Mock-auth не защищает публичный интернет-сервис.

## 3. Главный сценарий на итоговую сдачу

Пользователь A входит в демо-аккаунт → создает курс «АКОС» → «Новый» → «Сгенерировать конспект» → выбирает видеофайл (или URL, если путь готов), прикрепляет PDF и выбирает «Лекция» → создает задачу → видит ее в очереди, может перейти в другую часть сайта и вернуться → локальный worker выполняет новый изолированный адаптер Whisper → Codex или Claude CLI без вызова исходной функции `konspekt` → появляется конспект Markdown с вложениями → пользователь читает его в трехколоночном ридере, открывает Milkdown, исправляет абзац, сохраняет → скачивает `.md` → пользователь B с доступом к общему курсу видит документ. Для 19 ноября главная демонстрация должна работать с **одним реальным локальным видео**, не требуя внешней публичной публикации.

Второй обязательный итоговый путь: в любом курсе с правом записи «Новый» → «Создать заметку» → сохранённая пустая Note («Без названия», Markdown `''`) → общий Milkdown Crepe → ввести текст/переименовать → сохранить → открыть из дерева → refresh → экспорт `.md`. Видео, источник и GenerationJob не создаются. Пустое тело также можно сохранить и экспортировать. При ошибке или конфликте ревизии черновик сохраняется. Дополнение от 11 ноября реализовано в итоговой версии.

### Пять функциональных блоков первой версии

1. **Пространства и библиотека:** дерево курсов/папок/заметок; создание курса и пустой ручной Markdown-заметки, её открытие/редактирование/переименование/экспорт; личное и одно общее пространство, демо-переключение между двумя пользователями.
2. **Создание из источника:** форма URL или загрузки видео; PDF/PPTX при наличии рабочего адаптера; инструкции; предустановленные режимы «Лекция/Семинар». URL, не поддерживаемый `yt-dlp`, показывает понятную ошибку, а не ложный успех.
3. **Очередь:** сохраняемые задания, статусы `queued/acquiring/transcribing/preparing/generating/ready/failed/cancelled`, действия повтора/отмены ожидающей задачи, обновление состояния без потери после refresh. Последовательный worker.
4. **Ридер и редактор:** Quartz-подобный Explorer, TOC, Markdown/KaTeX/картинки/код, режим WYSIWYG (Milkdown Crepe), режим исходного Markdown (CodeMirror), сохранение и `.md` экспорт. Изображения и формулы должны оставаться работоспособными после сохранения.
5. **Совместная библиотека и видимость:** участники общего курса `owner/editor/viewer` с правами просмотра/редактирования; наследуемый от курса доступ, защита от случайного перезаписывания устаревшей ревизии.

### Явно НЕ входит в ИДЗ1

Настоящая публичная SSO-авторизация; безопасная публикация личных документов в интернете; Google-Docs realtime; генерация всех форматов и загрузка с защищенных сайтов; импорт всего Obsidian vault; конструктор произвольных промптов; синхронизированный видеоплеер/слайды/транскрипт; граф с полноценным поисковым индексом; автоматическое создание Git-коммитов и push в hse-notes; платная BYOK-система для каждого пользователя.

## 4. Как обойтись без редактора с нуля и что делать с Quartz

- **Milkdown Crepe** — первый готовый WYSIWYG редактор; отдельный **CodeMirror** для исходного Markdown подключается после завершения основного сценария; единый Markdown как источник истины. Перед подключением проверить round-trip на GFM-таблицах, блоках кода, `$$` формулах и изображениях. В MVP можно ограничить поддерживаемый синтаксис и явно указать это в интерфейсе.
- **Quartz не является динамической CMS**: он берет Markdown из `content/` и строит статические страницы. Нельзя считать его готовым backend для авторизации, совместных правок и приватного контента.
- **Для ИДЗ:** сначала ограниченный 60 минутами эксперимент с оригинальными компонентами Quartz 5; стабильные компоненты переиспользуются в React через Preact. Если мост требует значительных изменений, используется согласованный готовый react-markdown/remark/rehype renderer и стили Quartz; UI-стили, поведение Explorer/TOC и существующий контент-формат можно адаптировать, не переписывая редактор. Не обещать, что весь React UI запущен на движке Quartz.
- **Для развития:** отдельный fork Quartz v5 для *публичного* экспорта из LectureVault (Markdown+assets в `content/`, сборка/публикация). Не включать приватные/«по ссылке» заметки в публичную сборку. Рабочий существующий `hse-notes` не менять без согласия.
- **Перед выбором версии:** Codex должен проверить текущую установленную версию в `hse-notes`, сравнить с v5, оценить совместимость, **не выполнять миграцию автоматически**.

## 5. Технический план

- **Frontend:** React + TypeScript + Vite; Tailwind + shadcn/ui (готовые элементы приложения); Milkdown Crepe + CodeMirror; `react-markdown`/remark/rehype либо совместимый рендерер с KaTeX для read-only. Не собирать rich-text с нуля.
- **Backend:** FastAPI + SQLite + `storage/` с раздельными папками заданий и вложений; URL/file/metadata API; ACL контролирует backend, а не только скрытые кнопки UI.
- **Worker:** одна задача одновременно; persist state *перед запуском*; после crash задачи в `running` не исчезают, переходят в interrupted/failed с возможностью повтора; команды запуска через безопасный `subprocess` и валидированные аргументы.
- **Generation adapters:** mock и изолированный Whisper → Codex/Claude, включаемые явно. Функцию konspekt и .bashrc не загружать; переиспользовать проверенные инструменты через новый изолированный адаптер. Не менять оригинальные файлы пользователя и не выполнять экспорт/commit/push автоматически.
- **Auth:** два демо-аккаунта для сдачи, без паролей; реальный открытый интернет-сервис с таким login небезопасен. Аккаунт Claude/Codex CLI существует только на сервере; никогда не принимать его credentials в браузере.
- **References:** `docs/reference/{quartz-user,obsidian-user,notion-user,editor-user}.png` — скриншоты, предоставленные пользователем.

### Сущности

`User`, `Workspace`, `WorkspaceMember`, `Course`, `Folder`, `Note` (`markdown`, `revision`, `visibility`, `owner_id`), `NoteAsset`, `NoteSource`, `GenerationJob` (`status`, `current_step`, `error`, `created_by`, `note_id`), `GenerationPreset`. Модель данных может быть упрощена для MVP без потери основного сценария.

Note едина для обоих сценариев; `origin: manual/generated` различает происхождение, связь с источником/job необязательна. Сгенерированные и ручные документы имеют общий editor, ACL/revision, сохранение, переименование и экспорт. Переименование не меняет ID/ссылку, ручная заметка не требует фиктивного задания. Совместимость существующих конспектов сохраняется.

Инфраструктура не должна задерживать основной сценарий.

## 7. Приемочные проверки

1. Создать курс, отправить корректный локальный видеофайл, дождаться результата, открыть статью с формулами/изображением (если источник их содержит), отредактировать абзац, refresh → правка осталась.
2. Отправить неподдерживаемую ссылку / файл неподходящего типа → ошибка рядом с соответствующим полем или в карточке задачи, без потери введенных настроек; очередь не зависает.
3. Создать общий курс от пользователя A; переключиться на B, открыть конспект; viewer не может редактировать, editor может; пользователь без доступа не получает документ через API.
4. Проверить отмену *queued* задачи и повтор после failed; refresh или рестарт backend не теряет очередь.
5. Переключить Markdown ↔ WYSIWYG; заголовки, формулы, таблицы, ссылки и код не повреждаются. Если сложный Obsidian-синтаксис не поддержан, не импортировать его скрыто и не терять данные без предупреждения.
6. Проверить масштаб 1440px и 390px, навигацию, TOC, ошибки, пустые состояния и keyboard focus.
7. В личном и общем курсе с правом записи создать пустую заметку без видео: очередь не меняется; общий Crepe позволяет сохранить пустое тело, затем текст/формулы/таблицу/изображение/код, переименовать, открыть из дерева после reload и скачать Markdown. Viewer/посторонний не может создать/сохранить/переименовать через API; ошибка 409 не теряет черновик. Генерационный путь продолжает работать с той же Note и редактором.

**Секреты/публичность:** `private/unlisted/public` в mock-режиме — демонстрационная модель. Без настоящего login и серверного ACL нельзя публиковать такую сборку в открытом интернете.
